## 2. demo 标识与可追溯性

- 订单编号/工单编号使用 `DEMO-` 前缀（如 `DEMO-SO-20261010-01`）；SN 使用 `SN-DEMO-*`
- remark 字段统一写 `演示数据·非真实业务·生成于2026-10-16`（schema 允许的文本列）
- 生成脚本记录全部插入 ID 到 `%TEMP%\mes-demo-ids.json`（精确 ID 清单，清理时逐行按 ID 删除，**禁止 LIKE/前缀批量删**，遵守项目约定）
- 不触碰：sys_user / material / device / bom / process_route / ai_query_log / audit_log 的任何既有行

## 3. 生成方式

- 脚本：`scripts/generate-demo-data.mjs`（待授权后编写），复用 `backend/node_modules/mysql2`，配置经 `dotenv` 读 `backend/.env`，口令经进程环境变量（用户密钥存储）注入
- 事务：每张表一个事务；插入前校验前置（如 product=14、work_order 编号唯一）
- 幂等：执行前检查 `sale_order` 中是否已存在 `DEMO-%` 编号，存在则拒绝重复生成

## 4. 验证清单（生成后逐项实测）

1. F2 日报：POST /api/v1/daily-reports {date:今天} → 期望 answerStatus=answered，overview/linePerformance/alerts/suggestions 四段齐全，数字与库一致
2. F3 问数：「当日产量」「近 7 天产量趋势」「今天哪条产线直通率最低？」→ answered 且数字可核对
3. F4 根因：对真实 alert id 调 POST /api/v1/alerts/{id}/root-cause-analyses → possibleCauses/suggestion 返回
4. SN 追溯：GET /api/v1/sn-traces?sn=SN-DEMO-xxx → 命中工单级快照
5. 浏览器：订单/工单/报工/质检/预警/日报/问数/SPC/MRP/移动工作台页面显示真实数据、无控制台错误
6. 数据一致性：驾驶舱汇总 = 逐产线之和（契约 §日报口径）

## 5. 清理方式（验证完成后）

- 按 `%TEMP%\mes-demo-ids.json` 中记录的精确 ID 逐表 DELETE（顺序：report/qc_record/defect/alert/sn_trace/equipment_log → work_task → work_order → sale_order）
- 清理后校验各表计数回到生成前基线；product 14 行主数据保留（属主数据修复，非演示数据）
- 审计：清理动作本身记入 audit_log（经 API 或脚本均记录）
