## 一、项目目标

不走课程培训路线，只取企业的真实数据（痛点、需求、主数据），做一套完整系统：

- **基础功能层**：升级版 MES（比课程原方案 9 模块更强，见第三节）
- **AI 增强层**：4 个 AI 功能，生长在基础功能层之上（见第四节）

做完后向老师完整演示，并能讲清楚"哪些功能需要真实数据支撑、当前边界在哪里"。

```
┌─────────────────────────────────────────────┐
│ AI 增强层：RAG问答 / AI日报 / 智能问数 / 预警根因分析 │
├─────────────────────────────────────────────┤
│ 基础功能层：订单→工单→报工→检验→追溯→物料→设备→看板   │
├─────────────────────────────────────────────┤
│ 数据层：真实主数据（知识库/产品/设备/BOM…）+ 近7天演示业务数据 │
└─────────────────────────────────────────────┘
```

## 三、基础功能层（升级版 MES，原本功能）

> 来源：`docs/升级版MES设计方案.md`。核心定位：从"电子化纸质单据"升级为"让数据自己干活"。

| 编号 | 模块 | 对应痛点 | 一句话说明 |
|------|------|---------|-----------|
| B1 | 生产订单管理 | 痛点1 | 创建/确认生产订单，确认后自动生成工单 |
| B2 | 工单管理 | 痛点2 | 按工艺路线自动分解为工序任务；状态机：待启动→在产→完工 |
| B3 | 工序报工 | 痛点4 | 工位扫码 3 步报工（扫工单→输数量→确认），实时更新完工数 |
| B4 | 质量检验 | 痛点3 | 检验结果 OK/NG 录入；NG 自动创建不良品记录 |
| B5 | 物料管理 | 痛点5 | BOM 管理、批次入库、产品与物料批次绑定 |
| B6 | SN 追溯 | 痛点3 | SN 查全链路血缘图谱（工序→操作员→设备→物料批次→检验），一键导出追溯报告（满足 IATF 16949） |
| B7 | 设备管理 | 痛点6 | 设备状态机（运行/待机/维修/停机）+ OEE 自动计算 + 停机超时告警；预留 MQTT 接口 |
| B8 | 经营驾驶舱 | 痛点7 | 产量/质量/设备/交付多维看板，支持钻取；一键生成月报 |
| B9 | 用户权限+审计 | 多岗位协同 | admin/manager/operator 三级角色 + 操作审计日志 |
| B10 | 预警中心 | 新增 | 订单延期风险/库存不足/质量异常/设备停机，统一告警、分级推送 |
| B11 | SPC 质量分析 | 新增 | 不良品 Pareto 图、工序不良率趋势、直通率 FPY——从"记录不良"到"预防不良" |
| B12 | MRP-lite | 新增 | 订单+BOM 自动算料，生成采购建议；低于安全库存自动预警 |
| B13 | 移动端 PWA | 新增 | 手机扫码报工、扫码追溯；操作员/质检员/仓库员主力入口 |
| B14 | 开放 API | 新增 | 预留 ERP 对接、设备 IoT 对接的 REST 接口 |

**核心主线**（必须跑通的最小闭环）：建订单 → 自动生成工单 → 自动分解工序 →
扫码报工 → 检验录入 → 看板数字实时联动。

## 四、AI 增强层（4 个功能，长在基础层上）

### F1 · RAG 工艺知识问答
- **用户**：操作员、质检员
- **集成点**：独立知识库，可嵌入 B3 报工 / B4 检验界面做"工艺助手"
- **知识库**：需求背景文档全文 + 6 份 Excel 转成的 31 个知识块（已建成 knowledge.json）
- **要求**：
  1. 输入自然语言问题，返回答案 + 引用来源（来源名称 + 相关度）
  2. 编号类问题（如 EQP-SMT-006）必须精准命中对应行
  3. 资料中没有的信息，明确回答"资料中没有相关信息"，不编造
  4. 双模式：未配置 AI Key 时为本地抽取式回答；配置后切换大模型生成式回答

### F2 · AI 生产日报
- **用户**：厂长（每天上班第一眼看的东西）
- **集成点**：数据源 = B8 经营驾驶舱的指标；是驾驶舱的"文字版自动解读"
- **内容结构**：今日总览（产量/完成率/直通率）→ 产线表现表 → 今日预警 → AI 建议
- **要求**：
  1. 数据来源必须明确标注"演示数据"（基于真实主数据模拟）
  2. 预警条目 = F4 的输出，两者一致
  3. 建议部分与预警联动，不说空话
  4. 配置 AI Key 后可切换大模型润色版

### F3 · 智能问数（自然语言查生产数据）
- **用户**：厂长、计划员
- **集成点**：查询对象 = 基础层的业务数据（B2 工单 / B3 报工 / B4 检验 / B7 设备），不是孤立功能
- **要求**：
  1. 支持单日查询（如"今天 SMT-3 线直通率多少"）
  2. 支持近 7 天趋势对比（如"这周哪天不良率最高""SMT-3 线这周直通率趋势"）
  3. 回答必须带数字，数字必须与演示数据一致
  4. 问不到的数据明确说明，不编造
- **示例问题清单**（演示用，至少覆盖）：
  - 今天哪条产线直通率最低？
  - 这周哪天不良品最多？
  - SMT-2 线这周完成率趋势怎么样？
  - CAL-1 线的主要不良原因是什么？

### F4 · 预警根因分析
- **用户**：厂长（接收方）
- **集成点**：挂在 **B10 预警中心**之下，是预警中心的"AI 增强"——预警中心负责"发现"，F4 负责"解释"
- **预警规则**（演示数据上固定触发）：
  1. 质量预警：产线直通率 < 97%
  2. 交付预警：产线完成率 < 90%
  3. 设备预警：设备状态为"维修中"
- **要求**：
  1. 每条预警给出 1~2 条可能原因（关联同产线设备状态/物料批次/历史不良）
  2. 每条预警给出 1 条处置建议（具体可执行，如"将 SMT-2 线工单临时转至 SMT-1 线"）
  3. 与 F2 日报联动：日报中的预警列表即 F4 的输出

## 五、用户角色

| 角色 | 对应企业岗位 | 基础层功能 | AI 增强功能 |
|------|-------------|-----------|------------|
| 厂长 | 李厂长（admin） | B8 驾驶舱、全部查看 | F2 日报、F3 问数、F4 预警根因 |
| 计划员 | 赵计划/孙计划（manager） | B1 订单、B2 工单 | F3 问数（查进度、查延期风险） |
| 车间主任 | 刘/陈/赵主任（manager） | B2 工单、 B3 报工查看 | F3 问数（查本车间） |
| 操作员 | 产线操作员（operator） | B3 扫码报工 | F1 RAG 工艺问答 |
| 质检员 | 质检员（operator） | B4 检验录入 | F1 RAG 工艺问答 |
| 仓库员 | 仓库管理员（operator） | B5 物料批次操作 | — |

演示时按"厂长的一天"串起来：早上看日报（F2）→ 发现预警点开看根因（B10+F4）→
问计划员查进度（F3）→ 质检员查工艺确认（F1）→ 回到基础主线看工单流转（B1→B2→B3→B4）。

## 六、数据需求

### 6.1 真实数据（已验证，直接用）
- RAG 知识库：需求背景文档 + 6 份 Excel，共 31 个知识块
- 主数据：15 产品 / 13 设备 / 24 物料 / 23 账号 / BOM / 工艺路线
- 数据库表结构：`db/schema.sql`（18 张表：6 主数据 + 11 业务 + 1 AI 日志）

### 6.2 演示数据（需生成，明确标注，基础层与 AI 层共用同一份）
- **时间范围**：近 7 天（含今天）
- **覆盖业务**：7 条产线 × 每天：工单（B2）、报工（B3：产量/良品/不良）、
  检验（B4：OK/NG/不良类型）、设备状态（B7）
- **一致性要求**：
  - 固定随机种子，同一份代码每次生成的数据完全一致（演示可重复）
  - 设备维度与真实数据联动：EQP-SMT-006（回流焊炉）在演示数据中保持"维修中"，备注"加热区故障"
  - 数字自洽：日报总数 = 各产线之和；问数答案 = 同一份演示数据；看板数字 = 报工汇总
- **标注要求**：所有演示数据出现的位置必须带"演示数据"标识；知识库引用必须带来源名称

## 七、非功能需求

1. **本地可运行**：老师电脑上能跑起来，不依赖外网（除可选的大模型 Key）
2. **LLM 可插拔**：通过环境变量 `AI_BASE_URL / AI_API_KEY / AI_MODEL` 接入 OpenAI 兼容接口；
   未配置时自动降级为本地模式，功能照常演示
3. **响应时间**：问答 < 3 秒，日报告生成 < 5 秒，看板加载 < 3 秒（本地模式）
4. **诚实性**：任何"不知道/没有数据"的情况必须明确说明，不编造数字和结论
5. **技术栈**：待定（二选一：NestJS+Vue3 / Spring Boot+Vue3，用户拍板后冻结）

## 九、讲解文档（交付物之一）

单独一份《讲解要点》文档，包含：
1. **演示顺序**：开场（企业背景 1 分钟）→ 基础主线（B1→B2→B3→B4→B8 看板）→
   F2（厂长看日报）→ B10+F4（点开一条预警看根因）→ F3（现场提问趋势问题）→
   F1（操作员查工艺）→ 收尾
2. **每步操作**：点哪里、输入什么、预期看到什么
3. **话术**：每个功能 30 秒版本；重点讲"基础层解决纸质低效，AI 层让数据自己干活"
4. **Q&A 预案**（老师最可能问的）：
   - "数据哪来的？"→ 知识库与主数据是企业真实文档和 Excel；日生产数据是演示数据，已标注
   - "预测功能为什么没做？"→ 需要真实历史数据支撑（见第十节），当前只有主数据
   - "和课程原方案什么关系？"→ 原方案是"电子化单据"（9 模块）；这个是"升级版 MES（14 模块）+ AI 增强（4 功能）"，定位是超越不是重复
   - "AI 回答错了怎么办？"→ 带引用来源可核验；超纲问题明确拒绝回答不编造

## 十、边界与不做事项（给老师讲的核心话术）

| 不做 | 原因（诚实说明） |
|------|---------------|
| 不良率预测、排产优化、需求预测 | 需要连续数周/月的真实历史时序数据；当前只有主数据，没有生产流水数据 |
| 设备直连（MQTT/PLC） | 需要真实设备与网络环境；架构上已预留接口（B7） |
| 真实大模型接入 | 演示用本地模式即可；已预留环境变量接入，老师如需可现场配置 |

一句话话术："凡是需要'历史数据喂出来'的功能都没做，不是做不出，是诚实——没有真实数据硬做预测就是编数字。"
