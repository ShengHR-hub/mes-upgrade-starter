## 阶段一：建库 + 导数（先做，验证数据链路）

```powershell
# 1. 建库建表（会提示输入 root 密码）
mysql -u root -p < db/schema.sql

# 2. 生成种子数据（已生成好 seed.sql，如需重新生成：python db/seed_from_excel.py）
mysql -u root -p smart_mes < db/seed.sql

# 3. 验证行数（期望：product 15 / device 13 / material 24 / bom 28 / process_route 10 / sys_user 23；bom 为 28 是因为源 Excel 的 2 行成品行不计入，2026-10-10 已裁决）
mysql -u root -p -e "USE smart_mes; SELECT 'product',COUNT(*) FROM product UNION ALL SELECT 'device',COUNT(*) FROM device UNION ALL SELECT 'material',COUNT(*) FROM material UNION ALL SELECT 'bom',COUNT(*) FROM bom UNION ALL SELECT 'process_route',COUNT(*) FROM process_route UNION ALL SELECT 'sys_user',COUNT(*) FROM sys_user;"
```

如行数对不上，停下来报告，不要继续。

## 阶段二：三服务骨架（三个独立服务，端口固定）

| 服务 | 技术 | 端口 | 目录名 |
|------|------|------|--------|
| 前端 | Vue3 + Vite + Element Plus | 3000 | `frontend/` |
| 主后端 | NestJS + TypeORM + MySQL | 3001 | `backend/` |
| AI 服务 | FastAPI（复用 `ai-demo/` 已验证代码） | 8000 | `ai-service/` |

```powershell
# 后端骨架
npm i -g @nestjs/cli
nest new backend --skip-git --package-manager npm
cd backend
npm i @nestjs/typeorm typeorm mysql2 @nestjs/config
# 按 docs/升级版MES设计方案.md 建模块：orders / work-orders / reports / qc / devices / dashboard / alerts / auth

# 前端骨架
cd ..
npm create vite@latest frontend -- --template vue-ts
cd frontend
npm i && npm i element-plus axios echarts

# AI 服务（复用已验证的 ai-demo 代码）
cd ..
mkdir ai-service; Copy-Item ai-demo/rag.py, ai-demo/daily_report.py, ai-demo/knowledge.json ai-service/
cd ai-service
pip install fastapi "uvicorn[standard]"
# 封装三个接口：POST /ask（RAG问答）、GET /report（AI日报）、POST /nl-query（智能问数，阶段三实现）
```

每个服务跑起来后必须通过健康检查：
- `http://localhost:3001/health` → NestJS
- `http://localhost:8000/docs` → FastAPI（自动生成的接口文档页）
- `http://localhost:3000` → Vue3 欢迎页

## 阶段三：近 7 天演示数据生成器（Python 脚本）

在 `ai-service/` 下新增 `demo_data.py`，要求：
1. 基于真实主数据（7 条产线、15 产品、13 设备）生成近 7 天的工单/报工/检验/设备状态数据
2. 固定随机种子，同一份代码每次生成的数据完全一致
3. EQP-SMT-006（回流焊炉）在演示数据中保持"维修中"，备注"加热区故障"
4. 输出为 SQL 文件，可重复导入；所有数据在界面上标注"演示数据"
5. 数字自洽：日报总数 = 各产线之和；问数答案 = 同一份数据
