# S12 隔离验收演示指南

## 使用边界

仅使用获授权的隔离数据库。脚本只创建带本轮唯一前缀的临时账号并在结束时清理，不执行建表、清表或重导。密码在本地隐藏输入，不复制到聊天、日志或文件。

## 真实 MySQL 与 JWT

在项目根目录运行：

```powershell
.\scripts\verify-s12.ps1 -Database <隔离测试库名>
```

成功证据应同时包含：数据库 e2e 退出码 0、三角色登录和 HS256 校验通过、停用账号旧令牌返回 403/20004、角色变化对旧令牌即时生效、临时账号清理成功。缺少任一项只能记为无法验证。

## 浏览器与 PWA

使用 Chrome 和 Edge 各自打开 `/login`、`/mobile`，检查 DOM、登录后路由、控制台错误、manifest 的 `standalone`、Service Worker 注册及 Cache Storage 不含 `/api/`。再在真实移动设备检查安装、摄像头扫码、断网外壳和恢复网络后的提交结果。桌面浏览器模拟不能替代实体设备验收。

## 业务验收顺序

先由技术人员记录真实请求和响应，再由业务负责人按需求规格说明书逐项确认订单、工单、报工、质检、预警、AI 日报/根因、SPC、MRP 和移动工作台。生产数据必须脱敏或在只读副本验收，任何受限字段和演示数据标识都必须保留。

## 上线签批

上线批准至少需要业务负责人确认业务结果、技术负责人确认版本和安全边界、运维负责人确认备份/回滚/监控/发布窗口。技术审查报告只能作为输入，不能代替这些签批。
