## 3. 认证实现复审

代码确认 `JWT_SECRET` 合规时使用 HS256、固定 issuer/audience 和 2 小时有效期；`JwtIdentityResolver` 每次请求重新读取 `sys_user.enabled/role`，因此停用账号和角色变更不会沿用旧权限。`auth.db-e2e-spec.ts` 已覆盖三角色真实登录、令牌签名、停用即时失效和角色即时变化，但本轮未执行，因为当前会话没有隔离 MySQL 口令。

## 4. 未验证项

1. 真实 MySQL 多表事务回滚、REPEATABLE READ 多连接隔离、并发累计和真实 JWT HTTP 链路：需要获授权的隔离库及本地隐藏输入口令后运行 `scripts/verify-s12.ps1 -Database <隔离库名>`。不得连接生产库。
2. Chrome/Edge 真实 DOM、登录交互、控制台和页面闭环：Chrome CDP 代理未建立，Edge 未连接；本轮不宣称浏览器通过。
3. PWA 安装、摄像头扫码、断网导航及恢复提交：仅完成 manifest、`/mobile` 路由、Service Worker 静态边界检查；实体 Android/iOS 和真实 Chrome/Edge 移动环境未验收。
4. 生产数据验收、业务负责人签字和上线批准：均未由技术审查代签。

## 5. 产品边界

F1 RAG 当前仍未实现；B14 开放 API 保持未启用；B12 的可用库存、缺料和采购建议字段保持 `null` 并标注受限。上述状态不能在验收记录中改写为已交付能力。

## 6. 放行建议

技术上建议进入“隔离真实环境验证 → 业务场景验收 → 生产数据验收 → 组织上线签批”流程。只有真实环境证据和业务/运维责任人签批齐全后，才可作上线决定。
